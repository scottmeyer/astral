# Astral v0.1.0

Astral keeps agent work context alongside your code in Git. Select a subsystem
or saved projection, choose a work item, and launch Codex in a bound worktree.
Save an explicit native checkpoint for continuation or handoff, inspect recovery
plans, and review branch completion before applying it.

## Included

- A Git-backed `.astral/` index with core documents, subsystems, named projections
  and work records with merge-safe identifiers.
- Human-readable CLI output, explicit `--json`, and a searchable terminal picker
  for contexts and work items, with a final launch review.
- Fresh document launches, automatic worktree binding, worker status and
  diagnostics, explicit checkpoint save/resume, interrupted-operation recovery
  and reviewed fast-forward branch completion.
- Opt-in Git and Codex lifecycle advice, plus `astral commit` forwarding to Git.
- A Responses proxy with rolling projection support and opt-in native checkpoint
  tool rebinding on the qualified Codex route.
- The `astral-state` working-state helper and `stats` ledger utility.

## Install

Download the archive for your operating system and architecture and `SHA256SUMS`
from this release. Verify the archive's SHA-256 before extracting it. On macOS,
use `shasum -a 256 ARCHIVE`; on Linux, use `sha256sum ARCHIVE`; on Windows,
use `Get-FileHash ARCHIVE -Algorithm SHA256`. Compare against its entry in
`SHA256SUMS`. Each archive also contains a manifest with the source commit,
compiler version and hashes of the packaged files.

Extract into a new directory and copy `astral` (or `astral.exe`) to a directory
on your PATH. Keep the installed executable separate from a development build
directory. Close workers before replacing an existing installation. The helper
binaries are optional for the project workflow.

Source installation: `cargo install --path . --locked --bin astral` from the
`v0.1.0` checkout, using Rust 1.85 or newer.

## Compatibility and limits

- Archives are provided for Linux x86_64 (built on Ubuntu 24.04, glibc), macOS
  Apple Silicon and Intel (built on macOS 15), and Windows x86_64 (MSVC).
  The macOS downloads are not Developer ID signed or notarized.
- Bound worktrees, project filesystem operations, recovery, save and completion
  currently require Unix. The Windows build covers the proxy and other supported
  commands; it is not a claim of full Windows project-workflow support. Platform
  tests do not establish live Codex compatibility on every platform.
- Bound-worker and native checkpoint launches are qualified against Codex
  **0.154.0**. Native continuation requires explicit proxy routing on the tested
  OpenAI Responses Lite route. Authentication, executable tools and permissions
  come from the destination Codex runtime.
- Native transfer has same-account qualification. General cross-account/team
  portability, other model/provider protocols, and all runtime versions remain
  unqualified. No general token, latency or monetary savings are claimed.
- `astral finish` supports reviewed fast-forwards. Divergence, configured Git
  filters (including unused global filters), checkout conversions and certain Git
  policies require ordinary Git integration. Hooks never automatically save,
  commit, merge or change runtime permissions.
- Context freshness checks tied to subsystem code paths, delegated worker
  coordination and external issue synchronization remain future work.
